## GEO build directive — apply to ALL 50 (structure only; content/pedagogy is yours)

> **Goal:** these pages must be **cited by ChatGPT, Perplexity, Google AI Overviews, and Claude**, not just ranked. That rewards extractable, self-contained, entity-clear answers.
>
> 1. **Title = H1 = the exact target query** (verbatim where natural). e.g. *"What Is RAG? (Retrieval-Augmented Generation)"*, not *"Understanding Retrieval Systems."*
> 2. **Answer capsule first.** The opening block is a **40–60 word, self-contained, quotable answer** to the target question — define the entity by name in sentence one, no "in this lesson we'll…" preamble. This is the sentence an LLM lifts.
> 3. **Name the entity explicitly and consistently** every time (e.g. "the Model Context Protocol (MCP)"), never pronoun-only. LLMs match on entities.
> 4. **One sub-question per section.** H2s read as the questions people ask: *How it works · X vs Y · When to use it · Example · Common mistakes.* Each H2 opens with its own 1–2 sentence direct answer, then depth.
> 5. **Comparison lessons → a comparison table** (rows = options, columns = criteria). LLMs extract tables near-verbatim for "X vs Y" answers.
> 6. **End with a genuine 3–5 Q&A FAQ** using natural questions (the platform auto-emits these as FAQPage schema from the knowledge check, so phrase check questions as real user questions ending in "?").
> 7. **Quotable specifics over fluff** — concrete numbers, defaults, version names, one short code snippet. Vague prose isn't cited.
> 8. **Self-contained** — assume the reader arrived cold from a search/LLM; don't depend on other lessons for the core answer.
> 9. **Match search intent:** "what is / how does" → definition + mechanism; "how to build / tutorial" → numbered steps + code; "X vs Y" → table + decision rule.
>
> Do NOT change content depth or teaching style — this governs only the **first paragraph, headings, entity naming, and the FAQ**, so the crawlable page + FAQPage schema carry an answer the AI engines will quote.
